For changes to `~/.local/share/chezmoi/` (the chezmoi source tree), use a feature branch + PR workflow. Do **not** commit and push directly to `main`, even though it's a personal/solo repo.

**Why:** James wants CodeRabbit's PR-time review layer on dotfile changes — Codex's commit-time cross-provider review is one layer, CR is the second. Direct-to-main skips CR entirely. Validated 2026-05-14: pushed `54d422b` (tmux ⌘P sub-chat PR fix) direct to chezmoi main on the user's "go for it" — user pushed back: "why didnt we PR it to get the CR review?" Pick C (adopt PR workflow going forward) — the commit stayed on main, but future changes branch.

**How to apply:**
- Editing anything under `~/.local/share/chezmoi/`? Create a feature branch (`fix/...`, `feat/...`) before staging.
- `git push -u origin <branch>` and `gh pr create` instead of `git push` to main.
- CR runs against the PR — wait for its comments before merging.
- Merge via `gh pr merge` (squash) once CR + any other reviewers clear.
- Pairs with [[codex-dispatch]] (commit-time) — CR is the PR-time complement.
- Doesn't apply to runtime user files outside chezmoi source (`~/.tmux.conf` itself is generated by chezmoi apply — edit the source, not the destination).

**Exceptions:** trivial one-line corrections that don't benefit from CR review (typo in a comment, whitespace), but lean toward PR — the friction is low.
